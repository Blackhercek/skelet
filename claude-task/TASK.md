# Задание для Claude: выложить «Атлас тела человека» на GitHub Pages и проверить, что всё работает

Ты работаешь в репозитории с готовым проектом. У тебя есть доступ к репозиторию GitHub (и, надеюсь, к `gh` CLI). Задача: **сам опубликовать атлас на GitHub Pages и доказательно проверить, что он работает** — на компьютере и на телефоне (приоритет — iPhone). Отчитайся пользователю по-русски.

Пользователь — не программист. Он хочет: чтобы по ссылке атлас открывался на iPhone и других устройствах, устанавливался на экран «Домой» и работал без интернета. Приложение будут использовать в университетах (студенты и врачи), поэтому важна надёжность и точность.

---

## 0. Что это за проект (коротко)

- Интерактивный 3D-атлас тела человека на русском. Мужская модель (BodyParts3D, 2 234 детали), детальные сердце/лёгкие/мозг (HuBMAP HRA). Женская модель по просьбе владельца убрана (данные есть в истории git).
- Возможности: разведение структур слайдером, виды, слои/системы/области, поиск (русский/латынь/английский), карточка структуры, «Избранное», срез тела, снимок экрана, режим «Проверь себя» (тест), органы в 3D с метками, офлайн-режим (service worker), качество «Лёгкое/Высокое» (на телефоне по умолчанию «Лёгкое»).
- Только статические файлы. Сборка: `npm run build` → `dist/`. Все адреса относительные (`base: './'`), поэтому работает и из подпапки `https://логин.github.io/репозиторий/`.
- Данные лежат в `public/models/*.json` + `*.bin.gz`, `public/organs/*`. В `dist/` остаются только `.gz` (приложение распаковывает само).
- Автосборка и публикация уже настроены: `.github/workflows/pages.yml` (на push в `main`). Автопроверка опубликованного сайта: `.github/workflows/verify.yml`.
- Карта кода: `app/page.tsx` (интерфейс), `app/scene.tsx` (3D-тело), `app/organ-viewer.tsx`, `app/organs.ts` (органы и метки), `app/quiz.tsx` + `app/quiz-logic.ts` (тест), `app/regions.ts`, `app/localize.ts`, `app/offline.ts`, `public/sw.js` (service worker), `scripts/` (проверки и подготовка данных).

## 1. Правила

1. Ничего не ломай. Данные в `public/models` и `public/organs` не меняй. Не удаляй авторство и лицензии (CC BY 4.0 требует указывать авторов — они в приложении и в `public/ATTRIBUTION.md`).
2. Интерфейс только на русском. Не добавляй аналитику, трекеры, внешние шрифты и CDN — приложение работает автономно.
3. Коммиты небольшие, с понятными сообщениями на русском. Историю не переписывай, `--force` не используй.
4. Секреты/токены не коммить и не печатай в отчёте.
5. Сделать репозиторий публичным, сменить его имя, подключить домен или потратить деньги — **только после вопроса пользователю**. Если репозиторий приватный и GitHub Pages на его тарифе недоступны — остановись и спроси, как поступить.
6. Если что-то невозможно проверить (например, нет настоящего iPhone) — скажи об этом прямо, не выдавай непроверенное за проверенное.

## 2. Подготовка и локальные проверки

```sh
node -v        # нужен Node.js 22.13 или новее; иначе установи подходящий (nvm/fnm)
npm ci --ignore-scripts --no-audit --no-fund
npm run validate   # типы + 8 скриптов проверки данных/логики; всё должно пройти
npm run build      # должна появиться папка dist/ (≈115 МБ), без ошибок
```

Если `validate` или `build` падают — разберись и исправь причину (не «глуши» проверки). Все проверки были зелёными на момент передачи проекта.

## 3. Публикация на GitHub Pages

1. Определи репозиторий: `gh repo view --json nameWithOwner,visibility,defaultBranchRef` (или `git remote -v`). Основная ветка — `main`.
2. Убедись, что в репозитории есть `.github/workflows/pages.yml` и что он в `main`. Если репозиторий ещё пустой — `git add . && git commit && git push -u origin main` (проект ≈235 МБ, самый большой файл 13,6 МБ — лимит GitHub 100 МБ не превышен; при обрывах `git config http.postBuffer 524288000` и повторить, при необходимости пушить по частям).
3. Включи Pages с источником «GitHub Actions»:
   ```sh
   gh api -X POST repos/{owner}/{repo}/pages -f build_type=workflow   # если уже включено — вернёт 409, это нормально
   gh api -X PUT  repos/{owner}/{repo}/pages -f build_type=workflow   # на случай если включено с другим источником
   ```
   Если прав на это нет, попроси пользователя одним сообщением: *Settings → Pages → Build and deployment → Source: GitHub Actions*.
4. Дождись сборки: `gh run list --workflow pages.yml --limit 1`, затем `gh run watch <id> --exit-status`. При падении — `gh run view <id> --log-failed`, исправь и повтори.
5. Узнай адрес: `gh api repos/{owner}/{repo}/pages --jq .html_url`. Обычно `https://<владелец>.github.io/<репозиторий>/`. Дождись, пока `curl -sI <адрес>` вернёт `200` (иногда 1–3 минуты после деплоя).

## 4. Проверка опубликованного сайта (обязательна)

### 4.1. Быстрая проверка файлов по HTTP

Подставь адрес в `BASE` (со слэшем на конце) и убедись, что везде `200` и размеры правдоподобны:

```sh
BASE="https://<владелец>.github.io/<репозиторий>/"
for f in "" index.html manifest.webmanifest sw.js favicon.svg apple-touch-icon.png icon-192.png icon-512.png icon-maskable-512.png \
         models/atlas.json models/atlas-lite.json \
         models/names-ru.json models/names-la.json models/body-lite-0.bin.gz organs/organs.json organs/organs.bin.gz; do
  printf '%-34s ' "$f"; curl -s -o /dev/null -w '%{http_code} %{size_download} байт  %{content_type}\n' "$BASE$f"
done
```

Обрати внимание: у `manifest.webmanifest` тип должен быть JSON-подобным, `sw.js` — JavaScript. Проверь, что размеры `*.bin.gz` совпадают с `gzipBytes` из соответствующего `models/*.json` (так видно, что файл не повреждён и не подменён).

### 4.2. Автоматическая проверка в настоящих браузерах (Playwright)

Скрипт `claude-task/verify-deployed.mjs` прогоняет сценарии в Chromium (компьютер, телефон) и **WebKit с профилем iPhone** (WebKit — тот же движок, что в Safari на iPhone), снимает скриншоты и пишет отчёт в `claude-task/out/`.

```sh
npm install --no-save playwright          # не коммить package.json/package-lock.json после этого!
npx playwright install --with-deps chromium webkit
node claude-task/verify-deployed.mjs "$BASE"
```

Скрипт **не запускался автором** (в среде разработки не было Playwright) — это рабочий черновик. Если он падает из-за самого скрипта (селектор, таймаут), исправь скрипт, а не подгоняй результат. Сверься с кодом приложения (`app/page.tsx` и др.).

Что он проверяет:
1. Загрузка без ошибок в консоли, без неудачных запросов и ответов ≥ 400.
2. Стартовый экран: «Загрузка», процент и подпись «Сделано для Женьки»; интерфейс под ним закрыт; после загрузки экран исчезает (файлы моделей для этого замедляются).
3. Счётчик «Видимых структур: 2 229» (мужская модель). Холст WebGL реально рисует (сравнение скриншотов с холстом и без него).
4. Поиск по-русски, выбор структуры, карточка («Описание», русское название).
5. Режим «Проверь себя»: запуск, ответ на вопрос, обратная связь.
6. Органы в 3D: лёгкие, сердце, мозг; появляются метки; открывается карточка метки.
7. Срез тела (панель, выбор плоскости).
8. Настройки → «Скачать для работы без интернета» → **отключение сети** → перезагрузка: атлас должен открыться из кэша (`context.setOffline(true)`). Это главное доказательство офлайн-режима.
9. Телефон 390×844: нет горизонтальной прокрутки, нижняя панель и кнопки видны.
10. Профиль iPhone в WebKit: то же самое в сокращённом виде. Если в headless-WebKit нет WebGL, скрипт честно пометит это как «не удалось проверить», а не как успех.

После запуска **открой скриншоты из `claude-task/out/` и посмотри глазами**: тёмная тема, модель видна по центру свободной области, нет наложения панелей, нет «чёрного экрана», русский текст не обрезан. Сравни десктопный и телефонный вид.

### 4.3. Автопроверка на GitHub

`.github/workflows/verify.yml` запускает тот же скрипт на GitHub после каждой публикации и сохраняет отчёт как артефакт. Убедись, что он проходит (`gh run list --workflow verify.yml`). Если падает из-за самого workflow (версии, права) — исправь.

## 5. Если что-то не работает: где искать

| Симптом | Вероятная причина | Где смотреть |
| --- | --- | --- |
| Белая страница / 404 на файлах | пути не относительные или Pages отдаёт из другой папки | `vite.config.ts` (`base: './'`), `app/model-cache.ts` (`asset()`), вкладка Network |
| Файлы `.bin.gz` «битые» / «загружен не полностью» | сервер отдаёт `Content-Encoding: gzip` или меняет тело | `app/model-download.ts` (обрабатывает оба случая); сравни размер с `gzipBytes` |
| Service worker не регистрируется | не `https`, ошибка в `public/sw.js`, неправильный scope | `node scripts/validate-sw.mjs`; консоль; `navigator.serviceWorker.getRegistrations()` |
| Офлайн не работает | данные не скачаны в `atlas-data-v1` | `app/offline.ts`, `public/sw.js`; Application → Cache Storage |
| Чёрный экран на iPhone | нет WebGL2/мало памяти | выбрать «Лёгкое» в настройках; `app/scene.tsx` (`WebGLRenderer`, float-текстуры), консоль |
| Русские названия не подставились | не загрузился `names-ru.json` | `app/localize.ts`, `scripts/validate-names.mjs` |

После любого изменения кода: `npm run validate && npm run build`, коммит, push, дождаться публикации, повторить раздел 4.
